# CAP features of the Customer Messages application

This page maps every feature of SAP Cloud Application Programming Model (CAP) that the application
uses to the files that implement it, the commands to try it and the tests that prove it. The README
explains what the application does; this page tells where to look.

`test/docs/features.test.js` checks this page: every path and every npm script named here exists, and
every test file, model file, service file and request file of the repository is named here. A new file
fails the test until it is added to the page.

## Commands

| Command | What it does |
|---------|--------------|
| `npm run cds-watch` | Starts the application with live reload on <http://localhost:4004> (`cds watch --open`) |
| `npm start` | Starts the server like production does (`cds-serve`); `NODE_ENV=production` selects the production profile |
| `npm test` | All tests (`jest` with `@cap-js/cds-test`, in-memory SQLite, no network) |
| `npx jest test/srv/tags.test.js` | One test file; use any path from the tables below |
| `npm run lint` | ESLint with the CAP and CDS rules, no warnings allowed |
| `npx cds compile srv --to sql` | Compiles the model to SQL (a quick check of the model) |
| `npm run build` | `cds build --production`, writes the deployable artifacts to `gen/` |
| `npm run openapi` | Writes the OpenAPI documents to `docs/openapi/` |
| `npm run asyncapi` | Writes the AsyncAPI document to `docs/asyncapi/` |
| `npm run types` | Generates the types of the model to `@cds-models/` |
| `npm run typecheck` | Type-checks the typed example with TypeScript |

The mocked users of the development profile are `viewer`, `agent` and `admin` (the password is the
user name), defined in `package.json` under `cds.requires.auth`. The tests start the application with
`test/helpers/server.js` and reset the sample data of `test/data/` before each test.
